# 标书生产工作台 MVP

本目录是本地 Web 版 MVP：使用工作区 `02_知识库/Markdown` 作为知识库，主线围绕招标解析、目录规划、章节生成、审查和成稿搭建标书生产流程。页面默认进入“核心编制”模式；接单、报价、交付和复盘等扩展能力收纳在“完整运营”模式中。

## 工作区结构

```text
F:\1600 套技术标\
├─ 01_原始标书库\        # 原始标书，只读归档
├─ 02_知识库\Markdown\   # Markdown、manifest、章节索引
├─ 03_生产系统\bid_writer_app\  # Web 应用、数据库、上传和素材
└─ 04_交付与报告\        # DOCX、ZIP、PDF预检和验收报告
```

运行数据库和过程素材留在 `03_生产系统\bid_writer_app\data`；正式导出和质量验收文件统一写入 `04_交付与报告`，避免中间文件混入客户交付目录。

## GitHub边界

建议将本目录作为独立Git仓库同步。仓库只提交后端、前端、静态页面、测试、启动脚本、README和`.env.example`；`data`、SQLite、原始标书、知识库Markdown、视觉素材、导出文件和真实密钥均不进入仓库。

## 当前实现

- `backend/bid_writer`：核心业务模块，使用 SQLite + FTS5。
- `backend/bid_writer/app.py`：FastAPI 入口。
- `backend/bid_writer/server_stdlib.py`：无外部依赖的本地 Web/API 入口，当前环境可直接使用。
- `frontend`：React/Vite 工作台源码。
- `static`：无构建依赖的浏览器工作台，由 stdlib 服务直接托管。
- `data`：数据库、上传文件、导出文件。

已实现的 MVP 功能：

- 知识库全量索引：3024 份已入库文档、8 万余章节、10 万余检索片段。
- 知识库体检：按 manifest 与 SQLite 索引对账，展示总数、重复跳过、待 OCR、未索引、缺 Markdown、行业分布和按目录未入库原因。
- OCR 补录队列：列出 manifest 中待 OCR 的 PDF、文件是否存在、大小、页数预检、失败原因和 token 配置状态；只有人工点击单条补录时才调用外部 OCR，并在成功后写回 manifest、保存 Markdown、索引入库。
- 项目列表：查看已创建招标项目、要求数、草稿数。
- AI 生成配置：页面显示 OpenAI-compatible 模型是否已配置、当前协议、模型地址和连通性检测结果；同时兼容 Responses API 与 Chat Completions API，未配置密钥时章节生成自动使用本地保底草稿。
- 项目总览：打开项目后集中显示订单状态、章节进度、质量分、必要资料、沟通待跟进、主要风险和下一步动作。
- 生产指挥台：打开项目后聚合当前判断、下一步动作、关键指标、流程进度、阻碍提醒和主要风险，并可从面板直接触发生成目录、批量生成、质量审查、导出交付包等动作。
- 生产启动包：聚合接单判断、报价建议、必要资料缺口、渠道边界、开工清单、客户接单回复和订单确认话术，明确闲鱼等平台只做人工确认后的半自动交付。
- 新单生产向导：把客户询盘、接单判断、生产任务、订单确认、资料补齐、招标解析、目录章节、质量审查、交付包和结案复盘串成可点击的分步路线，并提供推荐话术复制。
- 渠道运营助手：面向闲鱼、微信等渠道生成商品说明、接单回复、资料催补、订单确认、进度说明、交付说明、结案和售后边界话术；只做复制素材和人工确认清单，不自动登录平台、不自动收款、不自动点击发货。
- 项目生产履历：自动汇总项目创建、文档处理、客户沟通、报价、收款、资料、目录、章节、校正、成稿、交付、反馈、结案、复盘和案例沉淀，形成可追溯时间线。
- 订单生产看板：汇总项目总数、逾期、48 小时内到期、未处理反馈、已结案数量、生产阶段和下一步待办，便于内部排产。
- 项目复盘台账：汇总已结案项目、待复盘项目、成交额、高风险案例和可复用案例，便于判断哪些标书类型适合继续接。
- 案例资产沉淀：可把单个草稿或当前项目全部草稿沉淀为可复用资产，维护标签、评分和摘要，并在后续检索与章节生成中优先作为“案例资产”返回。
- 生产状态自动同步：根据招标解析、目录规划、章节生成、导出交付、客户确认、返工反馈和结案确认，自动推断待解析、待生成目录、生产中、待导出、待客户确认、已交付、返工处理、已结案等状态。
- 生产流程看板：展示项目资料、招标解析、目录规划、章节草稿、覆盖审查、导出 Word、交付、反馈、客户验收结案和项目复盘沉淀的当前状态与下一步建议。
- 六阶段生产引导：项目页固定显示招标解析、目录策略、章节编制、图文配图、质量审查、成稿交付，只突出当前唯一主操作；解析、目录和审查确认均保存内容指纹，相关内容变化后自动要求重新确认。
- 项目可交付性评估：汇总接单、开工、交付三阶段的资料、付款、要求、目录、章节、质量、成稿和交付包状态，给出可接单、可开工、可交付或暂缓承接的判断。
- 一键生产流水线：可把当前项目从招标解析、目录规划、批量生成、覆盖审查、交付审查、ZIP 导出到状态同步串成一次操作。
- 一键客户交付准备：在生产流水线基础上继续导出客户发货包、执行客户包安全核验并生成客户发货确认单，外发仍需人工复制话术和确认发送。
- 质量门禁检查：生成质量分、分项检查和修订任务清单，覆盖资料缺口、缺章节、未响应条款、来源缺失、高风险审查问题、客户反馈、空泛内容和项目一致性问题；只审查目录当前关联的有效草稿，避免历史版本污染结果，并把本地保底稿、待确认占位符、生成过程说明、短章节和转义换行残留纳入阻断或提醒。
- 修订任务台账：把质量门禁发现的问题同步为可保存的处理台账，支持维护状态、负责人、截止时间和备注；已消除的问题会保留记录，并写入 ZIP 交付包。
- 最终核对清单：聚合响应覆盖、质量门禁、交付审查、交付记录和案例资产，支持人工逐项确认状态、负责人和备注，交付前形成可追溯核对记录。
- 整本成稿预览：按目录顺序组装整本 Markdown 成稿，显示章节进度、字数、缺章、风险提示和人工定稿确认状态；确认后记录确认人、备注和内容指纹。
- 全稿项目化校正：扫描旧项目名和不当承诺，支持预览并批量替换全部草稿，自动记录草稿版本和项目化校正留痕。
- 招标文件录入：支持粘贴文本，也支持上传 `.txt`、`.md`、`.docx`、可提取文本的 `.pdf`。
- 招标解析回填：解析时自动抽取项目名称、项目类型、结构形式、建设规模、层数、工期、质量目标、安全目标、招标范围、现场条件和特殊要求，并只在项目资料字段为空时回填，避免覆盖人工修正。
- 文档处理记录：上传 Word/PDF/Markdown/TXT 后自动记录处理方式、状态、提取字数、OCR 页数、OCR Markdown 输出路径和失败原因，便于追溯扫描版 PDF 或异常文件。
- 生产任务信息：记录客户名称、来源平台、订单号、联系方式、交付期限、预算金额、交付格式、生产状态和交付备注，为后续接单与交付管理打基础。
- 成稿格式设置：维护 DOCX 封面标题、副标题、投标单位、编制复核信息、页眉页脚、字体字号、目录页、响应矩阵、交付审查附录和章节分页选项。
- 投标单位资料：维护默认投标单位、资质能力、综合履约能力、质量安全体系、拟投入人员、机械设备资源、类似业绩和服务承诺；章节生成、质量门禁和交付包会自动引用。
- 接单助手：根据客户原始消息、招标要求、项目资料和生产任务，生成接单判断、报价区间、资料清单、风险提示和可复制客户回复，并可回填生产任务。
- 客户沟通台：按询盘、报价、资料催补、订单确认、交付、售后和结案阶段生成可复制话术，保存沟通记录、发送状态和内部备注；订单草稿会自动保存首条询盘记录。
- 报价规则中心：维护起步价、章节单价、条款单价、长文档加价、复杂项目加价、加急费、资料缺口预留、轻量折扣和报价上浮系数。
- 报价测算：按招标要求、预计章节、资料缺口、加急和复杂度生成价格区间、工作量、交付周期、加价折扣明细和可复制报价话术，并可保存报价记录。
- 收款记录：记录定金、尾款、全款或退款，汇总订单金额、已确认收款、待确认金额和未收金额；订单看板、项目总览、质量门禁、交付审查和交付助手会提示收款状态。
- 订单确认单：根据生产任务、接单评估和资料清单生成费用、交付范围、资料前提、修改轮次和不包含范围，支持复制给客户确认。
- 快速建项：客户先发来闲鱼、微信等渠道消息时，可直接创建订单草稿，自动预填生产任务并生成接单建议，后续再补招标文件进入正式生产。
- 草稿转正式项目：订单草稿收到完整招标文本或文件后，可补充到同一个项目并重新解析，系统会重置旧目录规划以避免条款错配。
- 资料清单追踪：自动生成完整招标文件、评分办法、项目基础资料、工期质量安全目标、图纸清单、企业模板等资料项，支持手工新增、更新状态、来源、负责人和备注。
- 项目资料收集：支持维护项目类型、结构形式、建设规模、层数、工期、质量目标、安全目标、承包范围、现场条件和特殊要求，章节生成会引用这些资料。
- 投标响应策略：根据招标要求、项目资料、目录规划和资料缺口生成总体定位、核心卖点、关键约束、风险控制、响应优先级和章节写作重点；支持人工编辑保存，并注入后续章节生成和交付归档。
- 响应矩阵：解析招标要求，支持人工新增、编辑、删除评分点/技术要求/废标风险，并可勾选指定要求参与章节生成。
- 响应矩阵挂接报告：展示每条招标要求当前挂接的目录章节、草稿响应状态和建议章节，支持后续补充条款自动挂接到目录。
- 目录规划：根据招标要求自动生成技术标章节清单，支持人工新增、改名、改序号、删除，并可逐章或批量生成整本草稿。
- 图文标书编排：以结构化文档块保存正文、原生表格、组织架构图、施工流程图、进度横道图、示例图片、提示块和分页；可按章节查看、编辑、删除和重新生成，不再把所有内容压成一段 Markdown。
- 可视化素材库：支持导入本地图片和从历史 DOCX 提取可用图片，记录原始文件、章节、用途和内容哈希；历史素材在成稿中标注来源与人工适用性复核要求，生成示意图会明确标注为非现场实景。
- 智能配图计划：扫描当前项目章节，分别列出确定性技术图、AI 混合施工场景和必须使用真实资料的证据图片，避免把三类素材混在一起使用。
- AI 混合施工示意图：AI 仅生成无文字施工场景底图，系统再叠加中文工序、顺序箭头、图题和用途声明；支持桩基、钢筋、混凝土、防水、机电、装修、安全文明和 BIM 八类场景。
- 图片证据边界：AI 场景图和历史参考图永远不能作为现场或业绩证据；用户上传的真实图片也只有在人工复核为“已通过”后才允许作为证据使用。素材库支持记录复核状态、备注、生成提示词、技术依据和标注数据。
- 工程图表生成：根据项目资料和目录自动生成项目管理组织架构、主体/防水/质量/安全/BIM 等流程图、施工总进度横道图、总平面功能分区示意图、PDCA 和 BIM 协同示意图。
- Word 图文排版：表格使用可编辑的 Word 原生表格，支持表头底纹、重复表头、防止行拆分、按内容分配固定列宽、图表自动编号与图表目录；章节正文中的 Markdown 管道表格也会自动识别为 Word 表格，不再原样显示竖线和分隔符。图片按版心等比缩放，页眉页脚、章节分页和图题保持统一。
- DOCX 正式预检：正式稿先执行 OOXML 结构审计，再由本机 Word 转为 PDF 并逐页栅格检查；空白页、内容触边、Markdown 表格残留、固定行高、缺图、内部字段泄漏或未完成预检都会阻止正式导出。
- 组织架构图：采用项目经理、项目管理层、职能部门的总线式层级布局，连接线只使用水平/垂直关系线，避免部门轮流挂接造成的斜线交叉和隶属关系歧义。
- 目录完整性审计：检查标准章节、施工工艺章节和未挂接招标要求，支持一键补齐缺失标准章节，并写入 ZIP 交付包。
- 响应覆盖检查：统计条款草稿覆盖率、目录生成进度、高优先级缺口和审查问题。
- 引用来源审计：集中检查每个章节的引用数量、来源是否仍能在知识库或案例资产中定位、是否过度依赖单一来源，以及是否有历史项目名残留风险；报告会写入 ZIP 交付包。
- 来源预览：检索结果和草稿引用可直接打开来源片段，查看知识库章节、案例资产正文、Markdown 定位路径和来源元数据，便于人工确认素材可信度。
- 交付审查报告：汇总生产任务、交付结论、检查清单、主要阻碍和处理建议，支持页面查看，并自动写入 Markdown / DOCX / ZIP 交付包。
- 交付放行单：汇总项目可交付性、交付审查、质量门禁、来源审计、成稿确认和 ZIP 核验，给出可放行、人工确认后放行或暂不放行的客户交付结论。
- 交付包清单核验：检查最新 ZIP 交付包是否存在、能否读取、核心交付文件是否齐全、结构化报告是否可解析，并把核验报告写入交付包。
- 客户发货包安全核验：检查最新客户发货包是否存在、能否读取、客户文件是否齐全，并扫描文件名、Markdown、TXT 和 Word 内容中是否误带报价、收款、来源审计、质量门禁、放行单、复盘等内部信息。
- 章节模板库：内置工程概况、施工部署、施工工艺及主要施工方法、重难点、质量、安全文明、进度、总平面、BIM、新技术、总承包管理等模板；支持在页面新增、编辑、覆盖和删除自定义模板，后续目录规划与章节生成会使用自定义模板。
- 模板覆盖度检查：可查看标准章节模板覆盖情况、缺失模板、默认/自定义模板数量，以及施工工艺库覆盖的工程类型和工艺要点。
- 章节生成：按行业、章节名、项目资料、投标单位资料、投标响应策略和要求检索历史片段；过滤封面、目录、授权书和碎片化素材，限制单一来源占比，再执行“初稿生成 + 总工终审重写”的两阶段生成。正文不得输出生成说明，不得编造缺失参数，未知事实统一使用 `【待确认：字段】`；施工工艺章节必须覆盖流程、准备、操作、质量、验收、安全、环保和成品保护。本地保底仅用于模型不可用时的应急草稿，质量门禁会阻止其被误认为正式成稿。
- 草稿管理：查看草稿列表、打开草稿、编辑后保存，自动记录版本并支持恢复旧版本；每份草稿会保留 LLM/本地保底生成方式、模型名和失败原因，可删除测试或废弃项目。
- 审查导出：检查未响应条款、旧项目名残留、来源缺失，并按目录顺序导出 Markdown / DOCX。工作版 Markdown 可随时导出，正式 DOCX/ZIP/客户包必须同时满足质量审查确认有效和整本定稿有效，前后端均执行门禁。
- 交付包导出：一键打包 Word 初稿、Markdown 备份、项目总览、项目生产履历、生产启动包、新单生产向导、渠道运营助手、成稿格式设置、投标单位资料、投标响应策略、生产任务、接单评估、客户沟通记录、报价测算、收款记录、订单确认单、资料清单、项目资料、目录完整性审计、响应矩阵挂接报告、响应覆盖报告、引用来源审计、生产流程状态、质量门禁报告、修订任务台账、最终核对清单、成稿确认报告、项目化校正记录、交付审查报告、交付说明、项目可交付性评估、交付放行单、交付包清单核验、结案确认单、项目复盘和案例资产，便于复核与归档。
- 客户发货包导出：单独生成可外发 ZIP，仅包含客户版 Word 初稿、Markdown 备份、客户发货说明、文件清单和 README，不包含报价、收款、来源审计、质量门禁、生产流程、放行单、复盘和案例资产等内部材料。
- 客户发货包安全核验：导出客户包后可一键检查文件白名单和内容风险；交付放行单会把客户包安全核验纳入放行判断。
- 客户发货确认：基于最新客户发货包、安全核验、未处理反馈和收款状态生成外发前确认单和客户话术；只在人工确认后记录客户包已发出，不自动登录闲鱼等外部平台。
- 交付记录归档：导出 ZIP 交付包时自动生成交付记录，可维护发送渠道、接收人、交付状态和备注，并支持标记为已交付。
- 交付助手：根据生产任务、交付记录和审查结论生成客户发货说明、交付文件清单和内部交付检查，便于在闲鱼、微信、邮件或网盘等渠道人工确认后发送。
- 客户反馈与返工：登记客户修改意见、关联章节、优先级、处理计划和负责人，流程看板与交付助手会提示未解决反馈，并支持标记为已解决。
- 客户反馈返工处理单：自动把未解决反馈匹配到目录/草稿章节，生成返工处理计划和客户回复话术，并可一键把反馈置为处理中、补齐处理计划。
- 返工执行改稿：在保留草稿改前版本后，为相关章节追加客户反馈响应补充，并把反馈推进到需复核，等待人工确认后再重新导出客户包。
- 客户验收与结案：根据交付包、客户收货状态、未处理反馈和订单确认单生成结案确认话术；仅在已交付且无未处理反馈时允许记录客户已确认，并把项目同步为已结案。
- 项目复盘沉淀：结案后记录成交价、成本、耗时、返工次数、客户满意度、风险等级、可复用评分、经验标签、可复用资产和经验教训，形成后续接单与报价参考。

## 环境变量

- `BID_WRITER_WORKSPACE`：工作区根目录，默认自动识别为当前 `F:\1600 套技术标`。
- `BID_WRITER_RAW`：原始标书目录，默认使用 `01_原始标书库`。
- `BID_WRITER_KNOWLEDGE`：知识库目录，默认使用 `02_知识库`。
- `BID_WRITER_DELIVERY`：交付与报告目录，默认使用 `04_交付与报告`。
- `BID_WRITER_DB`：SQLite 数据库路径，默认 `03_生产系统\bid_writer_app\data\bid_writer.sqlite`。
- `OPENAI_API_KEY`：可选，配置后章节生成会调用 OpenAI-compatible API。
- `OPENAI_BASE_URL`：可选，默认 `https://api.openai.com/v1`。
- `OPENAI_MODEL`：可选，默认 `gpt-4.1-mini`。
- `OPENAI_WIRE_API`：可选，支持 `chat_completions` 或 `responses`，默认 `chat_completions`。
- `OPENAI_MAX_OUTPUT_TOKENS`：可选，控制模型单次输出上限；施工工艺章节会使用更高的内部上限。
- `BID_WRITER_LLM_REVIEW`：可选，默认 `1`，启用第二阶段“总工终审”全文重写；设为 `0` 可关闭。
- `IMAGE_API_KEY`：可选，图片生成服务密钥；未配置时回退使用 `OPENAI_API_KEY`。
- `IMAGE_BASE_URL`：可选，图片生成服务基础地址；未配置时回退使用 `OPENAI_BASE_URL`。
- `IMAGE_API_URL`：可选，完整图片生成接口地址，优先级高于 `IMAGE_BASE_URL`。
- `IMAGE_MODEL`：可选，兼容 `/images/generations` 接口的图片模型名；未配置时系统仍会生成提示词，并允许导入外部底图完成程序化标注合成。
- `PADDLEOCR_TOKEN`：可选，配置后扫描版 PDF 会自动调用 PaddleOCR 解析为 Markdown 再入项目解析。
- `PADDLEOCR_JOB_URL`：可选，默认 `https://paddleocr.aistudio-app.com/api/v2/ocr/jobs`。
- `PADDLEOCR_MODEL`：可选，默认 `PaddleOCR-VL-1.5`。
