## 已补齐的网页流程

1. “项目资料”填写实际投标单位、签字人、专业复核人、截止日期和签章要求，保存业务资料不会自动重放旧签审。
2. 要求解析保留 PDF 来源页，归并换行和跨页评分表；已有草稿时禁止重新解析或重建目录，防止删除已写正文和签审依据。
3. 章节逐项处理确认事项，再由实际签审人确认当前正文。正文或项目资料修改后，相关签审失效。
4. “质量与交付”显示送审及正式版的独立门槛、已签审条款覆盖、整本预览、下载和历史版本。
5. 正式定稿须提供真实单位、实际复核人、当前正文签审、合规确认及整本定稿，系统不会自动勾选这些声明。

签审与编辑使用同一项目事务锁。导出在文件上传完成后、冻结记录写入前再次校验正文与完整签审状态；上传期间撤销、重新签审或更换复核人都会拒绝旧文件冻结。历史文件保持原始字节可下载，但失效版本不再标为当前版本。

DOCX、PDF 和 ZIP 使用独立导出目录，重复导出不覆盖旧文件。PDF 通过镜像内 LibreOffice 和 Python UNO 更新真实目录与页码，并发转换使用独立运行配置。普通 DOCX 保留可更新目录；最终页码以实际排版为准。
