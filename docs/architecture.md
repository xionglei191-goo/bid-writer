# 技术标生产与知识工程架构

## 系统边界

- `01_原始标书库`以只读卷挂载，应用不改写原件。
- PostgreSQL保存业务、版本、权限、任务、证据、审计和交付清单。
- MinIO保存标准文档、BM25索引、附件和冻结交付物；`04_交付与报告`保留本地镜像。
- Qdrant只保存已发布有效知识的dense向量和过滤字段。
- Redis和Dramatiq执行OCR、AI加工、索引、批量生成与导出任务。
- BGE-M3和BGE reranker由内部模型服务加载，不对宿主机外部开放。

## 主流程

```text
只读原件 -> 标准化 -> 章节切片 -> AI抽取 -> 独立复核 -> 规则检查 -> 最终裁决
                                                        |              |
                                                        v              v
                                                     异常待办       低风险发布
                                                                       |
                                                                       v
招标要求 -> 覆盖矩阵 -> 检索计划 -> BM25 + dense -> RRF -> rerank -> 证据快照
                                                                       |
                                                                       v
                    DOCX/PDF <- 冻结清单 <- 质量门禁 <- Claim证据核验 <- 章节生成
```

## 不变量

1. 未发布、已停用、失效或无权限知识不得进入检索结果。
2. 高风险知识不得自动发布；低风险自动发布必须通过来源规则、独立复核和最终裁决。
3. 自动发布批次抽检失败时整批撤回并重建索引。
4. 每次生成固定项目输入、知识、检索、模型、提示词和规则版本。
5. 高风险Claim缺少来源时不得签审或导出。
6. 正文或项目输入变化后，签审、证据状态和交付清单立即失效。
7. 审计事件使用前序哈希形成可验证链，业务接口不提供删除审计事件的能力。

## 部署拓扑

`docker-compose.yml`包含app、worker、PostgreSQL、Redis、Qdrant、MinIO和embedding服务。Prometheus与Grafana通过`monitoring` profile启用。首版是单组织私有化部署，不包含多租户、计费、GraphRAG或多智能体平台。
