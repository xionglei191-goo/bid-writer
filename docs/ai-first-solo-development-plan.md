## 2. 背景与约束

项目当前已经打通“原始资料—知识加工—审核发布—检索生成—质量门禁—DOCX 交付”的本地 MVP，但开发、知识整理、测试和业务验收主要由一人承担。原研究报告提出的 5～6 人工程化路线不适用于当前资源条件。

下一阶段不以大规模人工标注、完整 SaaS 平台或复杂 Agent 为前提，而采用以下路线：

> AI 批量处理，规则全面校验，人工只处理高风险、低置信度和模型冲突的例外项。

AI 可以替代大部分机械加工和初步复核，但不能替代知识发布责任、重大技术判断和正式交付签审。

## 3. 阶段目标

### 3.1 总体目标

优先完成一个专业方向的可信闭环：

```text
招标文件可靠解析
-> 要求、评分点和否决项结构化
-> 已发布知识的混合检索
-> 带来源证据的章节生成
-> 自动质量检查和模型交叉复核
-> 人工处理例外项
-> 冻结版本并导出 DOCX
```

### 3.2 第一阶段产品定位

1. 面向个人和小团队的本地工作台。
2. 优先支持单一行业或专业的真实技术标生产。
3. 保持本地资料、可选本地 OCR、可选本地 embedding 和可选本地模型能力。
4. 为以后企业单租户私有化保留模块和数据边界，但不提前建设完整 SaaS 能力。

### 3.3 成功标准

第一轮真实试点完成时，系统至少应满足：

- 从招标文件中提取高优先级条款，人工抽检漏答率低于 5%。
- 已发布知识检索 `Recall@10` 不低于 0.80，目标为 0.85。
- 所有进入可签审状态的强事实和强承诺均有来源或明确标记为项目输入。
- 引用可以定位到来源文档、章节或页码以及原文片段。
- 已停用、未审核和不适用知识不会进入正式生成上下文。
- 正文或引用发生变化后，原签审状态自动失效。
- 人工待处理项控制在全部 AI 处理结果的 5%～15%。
- 完成至少 2 个真实项目的端到端试运行。

## 4. 暂不实施的范围

以下内容在可信闭环通过真实项目验收前暂缓：

- 公有多租户 SaaS。
- Kubernetes 和完整微服务化。
- 多 Agent 自主协作平台。
- GraphRAG 和大规模知识图谱。
- 一次性加工全部历史标书。
- 同时覆盖多个差异较大的工程行业。
- 大规模人工数据标注项目。
- 与核心闭环无关的运营、计费和营销功能。
- 只改善界面视觉但不提升解析、检索和质量可信度的工作。

## 5. 核心实施原则

### 5.1 已发布知识仍是唯一生成边界

保持 ADR 0001 不变。AI 自动生成的知识只能进入候选区，必须经过自动校验，并根据风险等级进入自动候选发布或人工确认流程。未发布知识不得进入正式章节生成。

### 5.2 人工按例外处理，而不是全面审核

系统只把以下结果提交人工：

- 模型置信度低于阈值。
- 抽取模型与复核模型结论不一致。
- 规则检查发现数字、单位、日期、规范或项目专属信息。
- 涉及工期、人员、设备、业绩、资质、规范有效性和强承诺。
- 知识合并、替换或冲突处理。
- 将进入正式发布或最终交付的高风险内容。

### 5.3 同一模型不得在同一上下文中自我证明

关键任务采用独立步骤：

```text
抽取模型/提示词 A
-> 复核模型/提示词 B
-> 确定性规则检查
-> 必要时强模型裁决
-> 仍不确定时人工处理
```

可以使用同一模型供应商，但抽取和复核必须使用独立提示词、独立上下文和独立运行记录。高风险场景优先使用不同模型或更强模型复核。

### 5.4 所有 AI 处理必须可重放

每次 AI 运行至少保存：

- 任务类型。
- 输入内容哈希。
- 模型和供应商。
- 提示词版本。
- 结构化输入和输出。
- 温度及关键参数。
- 来源快照。
- 置信度和风险等级。
- token/费用统计。
- 创建时间和运行状态。

相同输入、模型和提示词版本优先复用缓存，不重复计费。

## 6. 数据与评测策略

### 6.1 三层数据体系

| 层级 | 产生方式 | 是否需要人工 | 主要用途 |
|---|---|---:|---|
| 黄金数据 | 人工确认的少量代表性样本 | 是 | 最终验收、回归测试、阈值校准 |
| 白银数据 | AI 生成并经独立模型和规则复核 | 抽检 | 检索评测、知识扩充、提示词迭代 |
| 普通数据 | AI 自动加工但尚未充分验证 | 否 | 候选知识、覆盖面探索，不直接作为高风险依据 |

### 6.2 最小黄金样本集

首个专业方向只建立：

- 10～20 份代表性历史技术标。
- 5～10 份招标文件。
- 30～50 条典型检索问题。
- 20～30 条人工确认的招标要求、评分点或否决项。
- 5～10 个高质量章节。
- 10～20 个典型错误案例。

黄金样本优先覆盖最常见和最高风险的业务情况，不追求数量。

### 6.3 AI 自动扩充评测数据

对每条已确认知识，让 AI 自动生成：

- 常规问题。
- 同义表达和专业术语表达。
- 招标文件可能出现的条款表达。
- 容易混淆的问题。
- 不应该命中该知识的负样本。

系统按知识来源自动形成预期命中关系。人工只抽检 5%～10%，并重点检查模型冲突和检索失败案例。

### 6.4 从真实使用中持续学习

以下行为自动沉淀为反馈数据：

- 采用或删除检索结果。
- 接受、修改或驳回生成段落。
- 修改前后内容差异。
- 确认或否定某条引用。
- 处理质量门禁问题的结论。
- 最终冻结并交付的章节版本。

反馈数据先用于评测、排序和提示词优化，不在缺少隔离和回滚能力时直接自动微调生产模型。

## 7. AI 知识加工流水线

### 7.1 标准流程

```text
来源文件登记
-> 文档解析/OCR
-> 页面和章节结构化
-> AI 文档分类
-> AI 知识拆解
-> 项目专属信息识别与脱敏
-> 适用条件、风险和有效性提取
-> 近重复和冲突检测
-> 独立模型复核
-> 确定性规则检查
-> 风险路由
-> 候选发布或人工待办
-> 发布索引
```

### 7.2 AI 分类输出

分类结果至少包括：

- 行业、工程类型和专业。
- 文档和章节类型。
- 知识类型。
- 是否含项目专属信息。
- 是否含高风险事实。
- 建议复用范围。
- 置信度。
- 不确定原因。

模型必须允许输出 `uncertain`，不得强制猜测。

### 7.3 知识单元结构

每个候选知识单元至少包含：

- 标题和知识类型。
- 整理后的正文。
- 对应原文片段。
- 来源文档、标题路径、页码或块位置。
- 适用工程类型和施工阶段。
- 前置条件和不适用条件。
- 工艺步骤、质量控制点和验收结果。
- 数值、单位、日期和规范引用。
- 项目专属信息列表。
- 风险等级和保密级别。
- 抽取置信度和复核结论。
- 内容哈希、提示词版本和模型版本。

### 7.4 风险分级

| 风险 | 示例 | 默认处理 |
|---|---|---|
| 低 | 不含数字的通用流程、普通管理措施 | 双模型和规则一致时进入候选自动发布 |
| 中 | 工艺步骤、质量措施、安全措施、设备建议 | 抽样审核或首次发布审核 |
| 高 | 工期、人员、设备数量、规范、资质、业绩、强承诺 | 必须人工确认 |
| 阻断 | 来源缺失、模型冲突、疑似旧项目残留、规范冲突 | 不得发布或生成 |

第一阶段即使低风险知识满足自动条件，也建议标记为“AI 候选发布”，通过真实项目验证后再逐步放开完全自动发布。

## 8. 检索与生成方案

### 8.1 检索演进

按以下顺序实施：

1. 保留现有 FTS5/BM25 作为关键词检索和回退。
2. 增加 embedding，并在单机阶段使用 FAISS 或本地 Qdrant。
3. 建立 BM25 与 dense 双路召回。
4. 使用 RRF 或等价方式融合。
5. 对候选结果使用 reranker 重排。
6. 按发布状态、行业、工程类型、知识类型、有效期和风险等级过滤。
7. 保存每次检索运行的查询、过滤条件、候选、分数和索引版本。

### 8.2 章节生成流程

禁止继续把“单次大模型输出”视为完成结果。章节生成拆为：

```text
要求解析
-> 章节任务规划
-> 检索查询规划
-> 知识召回和重排
-> 结构化初稿
-> Claim/事实/承诺抽取
-> 来源支持检查
-> 冲突和遗漏检查
-> 自动修订
-> 例外项人工确认
```

### 8.3 Claim 级证据

正文中的高风险 Claim 必须关联：

- 招标要求或项目输入。
- 来源知识单元及发布版本。
- 原文片段和定位信息。
- 支持程度。
- 自动复核结论。
- 人工确认状态。

无来源支持的强事实不得进入可签审状态。没有来源但属于方案建议的内容，必须明确标记为“建议/待确认”，不得写成确定承诺。

## 9. 质量门禁

### 9.1 四级门禁

| 层级 | 检查内容 | 执行者 |
|---|---|---|
| 确定性门禁 | 缺章、占位符、编号、项目名残留、失效引用、格式和必填项 | 程序规则 |
| 证据门禁 | Claim 是否有支持、引用是否相符、规范和参数是否可追溯 | AI 复核 + 规则 |
| 一致性门禁 | 跨章节工期、人员、设备、参数、范围和承诺冲突 | AI 复核 + 规则 |
| 签审门禁 | 技术合理性、废标风险和最终交付责任 | 人工 |

### 9.2 硬阻断条件

- 高优先级要求未响应。
- 否决项未处理。
- 强事实无来源或来源不支持。
- 引用了停用、未审核或超出适用范围的知识。
- 存在未处理的项目名称、人员、业绩或地点残留。
- 数值、工期、人员和设备在不同章节冲突。
- 正文修改后仍沿用旧签审。
- 导出文件预检失败。

### 9.3 人工待办界面

待办项应直接显示：

- 问题级别和类型。
- 当前文本位置。
- 来源原文和证据。
- 模型 A、模型 B 和规则的结论。
- 推荐处理方式。
- 接受、修改、驳回和暂缓操作。

人工不应为了确认一个问题来回切换多个页面或重新阅读整份原始文件。

## 10. 模型路由与成本控制

### 10.1 模型分层

| 任务 | 首选策略 |
|---|---|
| 文档分类、标签和简单脱敏 | 低成本模型或本地模型 |
| 知识拆解、要求抽取和复杂分类 | 中等能力模型 |
| 复杂表格、模糊条款和冲突裁决 | 强模型 |
| 章节生成 | 强模型，按章节调用 |
| Claim 与证据复核 | 独立强模型或独立复核提示词 |
| 相似度、聚类和检索 | embedding/reranker，不使用生成模型 |
| 电话、日期、金额、编号等 | 确定性规则优先 |

### 10.2 成本控制规则

- 相同内容哈希不重复处理。
- 仅处理新增或变更的文档和知识版本。
- 先使用低成本模型，低置信度时升级。
- 长文档按结构分段，避免重复发送全文。
- 批量处理非实时任务。
- 保存 token、费用、时长和失败率。
- 为单文档、单项目和单任务设置预算上限。
- 模型不可用或超预算时进入待处理状态，不静默生成低可信内容。

## 11. 实施路线

以下周期按一人主导、允许业务工作打断估算，建议使用阶段验收而不是强制固定发布日期。总体预计 14～18 周。

### 阶段 0：工程稳定化（第 1～2 周）

目标：修复会破坏可信性的现有问题。

任务：

- 清理 `production/service.py` 重复定义并拆分关键职责。
- 修复质量门禁未过滤失效响应证据的问题。
- 重构 `confirm_draft`，逐项保存处理决定。
- 建立内容哈希与签审失效机制。
- 统一模型、OCR 和路径配置。
- 统一错误码，停止向客户端暴露内部异常文本。
- 固定依赖并建立最小 CI。
- 为现有主流程增加回归测试。

验收：

- 所有现有测试通过。
- 重复方法定义清零。
- 失效证据不计入覆盖率。
- 草稿修改后旧签审自动失效。
- 关键接口出现错误时返回稳定错误码。

### 阶段 1：最小基准与运行记录（第 3～4 周）

目标：建立可衡量、可重放的开发基础。

任务：

- 选择首个专业方向。
- 建立最小黄金样本集。
- 增加 prompt registry、AI run 和成本记录。
- 定义 AI 结构化输出 Schema。
- 建立失败重试、缓存和人工待办状态。
- 增加基础检索评测脚本和报告。

验收：

- 至少 30 条黄金检索问题可重复评测。
- 每次 AI 运行可查到输入哈希、模型、提示词版本和输出。
- 相同输入可命中缓存。
- 非法结构化输出不会直接写入正式业务表。

### 阶段 2：AI 知识加工流水线（第 5～8 周）

目标：让 AI 承担 85% 以上的候选知识加工。

任务：

- 建立统一文档块、章节和知识单元模型。
- 接入 AI 分类、拆解、脱敏、适用性和风险识别。
- 增加独立模型复核和确定性规则检查。
- 实现模型冲突、低置信度和高风险路由。
- 建立知识来源对照和人工待办页面。
- 实现知识近重复和冲突建议，不自动删除原知识。

验收：

- 基准文档中至少 90% 能进入可解释的成功或明确失败状态。
- 每条候选知识均可定位原文。
- 高风险内容不会自动发布。
- 人工只需处理异常和高风险项，目标比例不超过 15%。
- 抽检的低风险候选知识忠实率不低于 90%。

### 阶段 3：混合检索与自动评测（第 9～11 周）

目标：证明检索能力显著优于当前纯关键词方案。

任务：

- 接入 embedding 和本地向量索引。
- 实现 BM25+dense 双路召回。
- 增加融合、reranker 和 metadata filter。
- 由 AI 自动生成白银查询和负样本。
- 建立失败查询分析和反馈记录。

验收：

- 黄金集 `Recall@10 >= 0.80`，目标 `>= 0.85`。
- 相比纯 FTS 基线有可量化提升。
- 未发布、停用和不适用知识命中数为 0。
- 检索结果保留来源、分数、过滤条件和索引版本。

### 阶段 4：证据化章节生成（第 12～14 周）

目标：生成内容从“参考了知识”升级为“关键结论可证明”。

任务：

- 结构化解析要求、评分点和否决项。
- 建立章节任务和检索规划。
- 增加 Claim、EvidenceLink、RetrievalRun 和 GenerationRun。
- 增加事实、数字、规范和强承诺复核。
- 实现证据不足时自动降级表述或生成待确认项。
- 在编辑器中展示来源侧栏。

验收：

- 高风险 Claim 引用定位有效率 100%。
- 人工抽检的引用支持准确率不低于 90%，后续目标 95%。
- 无支持的强事实无法进入可签审状态。
- 章节可重放其检索上下文、提示词和生成输出。

### 阶段 5：质量门禁与真实试点（第 15～18 周）

目标：用真实项目验证系统是否减少工作量并降低风险。

任务：

- 完成确定性、证据、一致性和人工签审四级门禁。
- 建立问题台账和例外处理界面。
- 建立冻结版本、交付 manifest 和文件哈希。
- 增加 DOCX/PDF 预检能力的最小实现。
- 完成 2 个真实项目试运行。
- 记录人工耗时、AI 成本、问题数量和最终修订比例。

验收：

- 所有硬阻断可以稳定复现。
- 修改后签审自动失效。
- 高优先级条款人工抽检漏答率低于 5%。
- 两个试点均能完成“解析—生成—审查—导出”闭环。
- 相比纯人工流程有明确的时间节省记录。

## 13. 指标面板

每个阶段至少跟踪以下指标：

| 类别 | 指标 |
|---|---|
| 文档处理 | 成功率、失败类型、平均耗时、OCR 使用率 |
| 知识加工 | 候选数量、自动通过率、人工待办率、抽检忠实率 |
| 模型运行 | 调用次数、token、费用、缓存命中率、结构化输出失败率 |
| 检索 | Recall@K、NDCG@K、无结果率、错误专业命中率 |
| 生成 | 章节成功率、Claim 数量、无证据 Claim 比例、自动修订率 |
| 质量 | 漏答、冲突、旧项目残留、误报、人工驳回率 |
| 效率 | 单文档人工处理时间、单章节人工修改时间、单项目总耗时 |

指标必须能够按模型版本、提示词版本和知识快照进行对比。

## 14. 单人工作节奏

每周采用固定节奏，防止研发、资料处理和真实业务互相挤压：

1. 周初选择一个可独立验收的小目标。
2. 先补测试或黄金样本，再修改实现。
3. 每次只改变一个主要变量，例如提示词、模型或检索参数。
4. 周中运行基准集，记录质量和成本变化。
5. 周末处理失败案例，更新待办和下一周目标。
6. 每两周形成一个可运行版本，不长期保留大范围未完成重构。

建议任务粒度控制在 0.5～2 天。超过 3 天的任务应继续拆分。

## 15. 风险与应对

| 风险 | 应对措施 |
|---|---|
| AI 看似合理但不忠实原文 | 强制原文引用、独立复核、规则检查和抽检 |
| 同一模型产生一致性偏差 | 使用独立提示词，关键任务使用不同模型或强模型裁决 |
| 费用快速增长 | 缓存、增量处理、模型分层和任务预算 |
| 资料外发风险 | 脱敏、供应商白名单、本地模型选项和明确外发标记 |
| 一人同时维护过多技术组件 | 保持模块化单体，优先 SQLite/本地向量库，推迟平台化 |
| 自动发布误判 | 第一阶段只自动进入候选发布，高风险始终人工确认 |
| 评测集被模型生成偏差污染 | 黄金集保持人工确认，白银集只作辅助指标 |
| 提示词或模型升级导致回退 | 固化版本，每次升级运行黄金回归集并保留回滚能力 |

## 16. 阶段退出条件

在以下条件满足前，不进入企业产品化和多租户建设：

- 至少 2 个真实项目完成闭环。
- 核心检索和证据指标达到本计划目标。
- 人工待办量稳定在可接受范围。
- AI 成本和处理时间可以统计和预测。
- 高风险知识和 Claim 没有绕过人工签审。
- 系统能够从运行记录重放关键生成结果。

满足以上条件后，再制定企业单租户私有化计划，重点建设 PostgreSQL、Qdrant、对象存储、异步任务、权限、审计、备份和安装升级能力。

### 阶段 2 首条纵向链路（2026-08-08）

已实现单文档 AI 知识加工最小闭环：

1. 每份标准文档采用一次批量拆解和一次独立批量复核，模型调用次数不随候选条数线性增加。
2. 候选知识必须包含章节编号、逐字来源引文、适用范围和风险等级，并通过结构化 Schema 校验。
3. 独立复核检查原文忠实性、项目事实残留、无依据参数和强承诺；确定性规则再次检查引文定位、电话、占位符、绝对承诺和数值参数。
4. 低风险候选在复核通过、置信度不低于 0.85 且无中高等级问题时可接收；中风险门槛为 0.92；高风险始终进入人工复核。
5. 候选与正式知识严格分表；接收后仅进入现有知识审核队列，仍需签审才能发布和参与检索。
6. 相同文档内容、模型配置、提示词版本和候选上限重复运行时复用既有流水线结果；模型或提示词变更会创建新运行，既避免重复计费，也保留对比能力。

下一步验收方式：从现有 10 份标准文档中选择 1 份代表性文档试运行，检查候选忠实率、异常比例和人工处理时间；达到预期后再扩展到 3～5 份文档，而不是一次处理全部资料。
